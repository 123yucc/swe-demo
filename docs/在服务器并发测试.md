# SWE-bench Pro 服务器并发测试指南

本文是后续批量运行 SWE-bench Pro 的通用操作手册，不只适用于前 20 个 case。目标是在本地局域网 Ubuntu 服务器上稳定跑完多个 case，收集 pass@1 结果、patch、日志和统计文件，并在磁盘有限的情况下保持 Docker 资源可控。

## 基本原则

- 正式指标是 pass@1：每个 case 生成一次 patch，做一次 SWE-bench eval。
- 不做 eval 后重修。eval 输出只用于统计和事后诊断，不进入同一次提交的修复闭环。
- API key 只通过环境变量注入运行进程，不写入 manifest、`.env`、日志或文档。
- 每个 `(model, issue)` 结束后必须清理 Docker 容器和镜像。
- 默认并发从 8 路试起；如果出现 OOM、exit 137、SSH 卡死或系统负载长期过高，降到 4 或 2。

## 服务器要求

推荐环境：

- Ubuntu Linux。
- 32GB 内存以上。
- 400GB 以上可用磁盘。
- 当前用户有 Docker 权限。
- Docker pull 可用；如需代理，Docker daemon 的代理必须能访问。

检查命令：

```bash
free -h
df -h . /var/lib/docker
docker info
docker ps
docker images
```

## 代理与 Docker Pull

如果服务器 Docker daemon 配置了本地代理，例如：

```text
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
```

需要从本机开反向隧道：

```bash
ssh -N -T -R 7897:127.0.0.1:7897 user@172.28.8.77
```

经验：OpenSSH 的 `-R` 比 Paramiko 反向转发更适合 Docker 大镜像下载。若 Docker 报：

```text
proxyconnect tcp: dial tcp 127.0.0.1:7897: connect: connection refused
```

先检查隧道是否还在：

```bash
ss -ltnp | grep 7897
docker pull hello-world
```

## Case 准备

每个 case 目录应满足：

```text
workdir/swe_issue_NNN/
  artifacts/instance_metadata.json
  repo/.git
```

如果服务器不能稳定访问 HuggingFace，不要依赖远端重新下载 dataset。可以从本地同步已有 `instance_metadata.json`，再按 metadata 拉 Docker 镜像并抽取 `/app`：

```bash
python3 scripts/fetch_issues_docker.py \
  --from-existing-metadata \
  --start-label <START_LABEL> \
  --count <COUNT>
```

脚本要求：

- `DOCKER` 默认使用 Linux 的 `docker`，不要写死 Windows Docker 路径。
- 当 metadata 没有 `dockerhub_tag` 时，从 `image_name` 推导 DockerHub tag。
- 拉取镜像时可尝试 `jefzda/sweap-images` 和 `123yucc/sweap-images`。
- 抽取 repo 后执行 `docker rmi -f <image>`，避免准备阶段占满磁盘。

准备完成后检查：

```bash
for n in $(seq <START> <END>); do
  i=$(printf '%03d' "$n")
  test -f workdir/swe_issue_${i}/artifacts/instance_metadata.json || echo "missing metadata $i"
  test -d workdir/swe_issue_${i}/repo/.git || echo "missing repo $i"
done
```

## Manifest

为每批实验创建单独 manifest，例如：

```json
{
  "models": [
    {
      "name": "gpt-5.2",
      "backend": "openai",
      "env": {
        "MODEL_BACKEND": "openai",
        "OPENAI_BASE_URL": "https://claude.buzz7.top/",
        "OPENAI_MODEL": "gpt-5.2",
        "OPENAI_API_SURFACE": "responses"
      },
      "output_subdir": "outputs_gpt-5.2"
    }
  ],
  "issues": ["021", "022", "023"],
  "max_workers": 8
}
```

注意：

- 不写 `OPENAI_API_KEY`。
- 每批 manifest 只包含计划运行的 issue，方便断点续跑和结果收集。
- `output_subdir` 固定为模型名相关目录，例如 `outputs_gpt-5.2`。

## 启动 Runner

只把 key 注入当前进程环境：

```bash
export OPENAI_API_KEY=...
python3 eval/local_swebench_runner.py \
  --manifest <manifest.json> \
  --max-workers 8
```

如果是补评测或恢复已生成 patch 的 case：

```bash
python3 eval/local_swebench_runner.py \
  --manifest <manifest.json> \
  --max-workers 8 \
  --redo-eval
```

运行中重点监控：

```bash
tail -f run_<batch>.log
free -h
uptime
docker ps
docker images
df -h . /var/lib/docker
cat workdir/local_runner_state.json
```

判断并发是否过高：

- 出现 `exit 137`、OOM、Docker daemon 无响应：立即降并发到 2。
- 负载短时升高可以接受；如果长期高负载导致 SSH 卡顿，降到 4 或 2。
- 内存 available 长期过低且 swap 明显增长，降并发。

## 必要 Runner 约束

这些约束应固化在 runner/evaluator 中：

1. 生成容器显式使用 bash entrypoint。

   某些镜像默认 entrypoint 不接受 `-c`，会报：

   ```text
   exec: "-c": executable file not found in $PATH
   ```

   创建 generation container 时应传 `--entrypoint /bin/bash`。

2. Docker 命令日志必须脱敏 secret。

   `docker create -e OPENAI_API_KEY=...` 不得原样写入日志。写入前把 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY` 等替换为 `<redacted>`。

3. Docker 输出文件 ownership 要正常化。

   eval 容器可能写出 root-owned 文件。runner 应在容器结束后 chown workspace，或避免把 workspace 文件复制到自身。否则会出现非 case 级 `PermissionError(13)`。

4. 每个任务 finally 阶段必须清理容器和镜像。

   成功、失败、异常都要执行：

   ```bash
   docker rm -f <container>
   docker rmi -f <image>
   docker image prune -a -f
   docker container prune -f
   ```

## 断点续跑

runner 会基于每个 case 的输出状态跳过已完成任务：

```text
workdir/swe_issue_NNN/outputs_gpt-5.2/
  patch.diff
  prediction.json
  run_metrics.json
  runner_task.json
  eval_result/eval_summary.json
  logs/
```

常见恢复方式：

- 只有 patch 没有 eval：用 `--redo-eval`。
- 有 checkpoint：runner 会继续 harness。
- 需要完全重跑某个 case：删除该 case 的 `outputs_gpt-5.2/` 或使用 `--force-restart`，删除前先确认不是要保留的实验产物。

## 结果收集

每批跑完后执行：

```bash
python3 scripts/collect_metrics.py \
  --output-subdir outputs_gpt-5.2 \
  --issues <ISSUE_LIST> \
  --output-dir workdir/eval_result_<batch_name>
```

或按前 N 个目录：

```bash
python3 scripts/collect_metrics.py \
  --output-subdir outputs_gpt-5.2 \
  --first-n 20 \
  --output-dir workdir/eval_result_gpt-5.2_first20
```

应生成：

```text
metrics_detail.csv
metrics_detail.json
metrics_summary.csv
metrics_summary.json
```

统计口径：

- `swebench_resolved` / `resolved` 是 pass@1 主指标。
- `harness_patch_outcome` / `patch_outcome` 只作为过程诊断字段。
- `build_gate_status` 只解释构建验证阶段，不代表最终 pass/fail。
- 不用 `PATCH_FAILED`、`PARTIAL_PATCH` 直接替代 pass@1。

## 结束审计

每批结束后必须检查：

```bash
docker ps -a
docker images
df -h . /var/lib/docker
```

检查必需文件：

```bash
python3 - <<'PY'
from pathlib import Path
missing = []
for issue_dir in sorted(Path("workdir").glob("swe_issue_*")):
    d = issue_dir / "outputs_gpt-5.2"
    if not d.exists():
        continue
    for rel in [
        "patch.diff",
        "prediction.json",
        "run_metrics.json",
        "runner_task.json",
        "eval_result/eval_summary.json",
        "logs/generate.log",
        "logs/eval.log",
        "logs/docker_cleanup.log",
    ]:
        if not (d / rel).exists():
            missing.append(str(d / rel))
print("missing_count", len(missing))
for item in missing:
    print(item)
PY
```

检查 key 是否落盘：

```bash
python3 - <<'PY'
import os
from pathlib import Path
secret = os.environ.get("OPENAI_API_KEY", "").encode()
hits = []
if secret:
    for base in [Path("eval"), Path("scripts"), Path("src"), Path("workdir")]:
        if not base.exists():
            continue
        for p in base.rglob("*"):
            if not p.is_file():
                continue
            try:
                if p.stat().st_size > 20_000_000:
                    continue
                if secret in p.read_bytes():
                    hits.append(str(p))
            except Exception:
                pass
print("secret_hits", len(hits))
for h in hits[:20]:
    print(h)
PY
```

最终报告至少包含：

- 总 case 数、success/failed/skipped。
- pass@1 resolved 数和 resolved rate。
- unresolved case 列表、`patch_outcome`、日志路径。
- Docker 清理结果。
- 统计 CSV/JSON 路径。
